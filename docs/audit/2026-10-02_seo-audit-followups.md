## S1 — Hydration: React error #421 (branch `feat/followups-s1-hydration`, 2026-10-02)
**Why / root cause.** Production showed React error #421 on `/carta-digital`, `/tarjetas-nfc` and `/tpv-restaurantes` (lab LCP 6.4s on carta, CLS 0.225 on NFC). `entry-client.tsx` called `hydrateRoot` immediately while every prerendered page was a bare `React.lazy(...)`. `React.lazy` throws its loader promise on a component's first render even if that promise already resolved, because the resolved payload only flips internally inside an async `.then`. With nothing preloaded first, the first hydration pass always suspended and React discarded the SSR DOM for a full client re-render — exactly what #421 reports.

**What changed:**
- **New `src/clientRoutes.tsx`** (design.md D1/D2): `preloadable(load)` memoizes one loader promise and tracks its resolved component. `Component` picks, via a mount-only `useState` initializer, between the resolved component (if `preload()` already settled) and a `React.lazy` fallback — so a preloaded route mounts its real component directly, no throw, no dehydrated boundary. `PRERENDERED_ROUTES` (8 non-home paths), `NOT_FOUND_ROUTE` (covers `*` and `dist/404.html`), `routeForPath()` (`"/"` → `null`, since App is static).
- **`src/entry-client.tsx`**: awaits `routeForPath(pathname)?.preload()` (catch → hydrate anyway) before `hydrateRoot`. Every page's `lazy(...)` became `PRERENDERED_ROUTES["/path"].Component`. `/admin` unchanged (`lazy()` + `createRoot`, never preloaded).
- **New tests:** `tests/unit/clientRoutes.test.ts` (loader called once, fallback before preload, resolved content with no Suspense needed after); `tests/unit/scripts/clientRouteParity.test.ts` (loader map ∪ `{"/"}` = `site-routes.json` = `entry-server.tsx` routes; only one `lazy(` left in `entry-client.tsx`, for `AdminPanel`).
- **Updated pre-existing test:** `tests/unit/route-registration.tarjetas-nfc.structure.test.ts` point 1 now asserts the `PRERENDERED_ROUTES[...].Component` shape instead of the removed `lazy()` shape. Points 2–4 untouched.

**Verification.** `npx jest` 1345/1348 (3 pre-existing unrelated `chatbotFlow.test.ts` network failures, same on `develop`). `npm run test:vitest -- --run` 112/112. `npx tsc --noEmit` clean. `npm run lint` clean. `npm run build` (owner-authorized): client+SSR+prerender succeeded, every prerendered page still ships its own chunk (no single-bundle regression), and the build's own `assertBodyUnchanged()` check passed for all 9 routes. `npx jest tests/unit/seo` 149/149 against the fresh `dist/`.

**Manual console check (task 1.8).** First pass against `vite preview` showed 18 `#418` hydration-mismatch errors on `/carta-digital` — a false alarm: `vite preview`'s default SPA fallback served `dist/index.html` (home) for the path `/carta-digital` instead of the nested `dist/carta-digital/index.html` (confirmed by byte/content comparison), a tooling gap unrelated to this fix (the old `lazy()` code hit the same wrong file and just masked it as another #421). Re-run against `npx serve dist` (clean-URL resolution, matching the real Vercel rewrites): **zero console errors on all 9 routes, `404.html` and the `/admin` SPA shell.** Local LCP/CLS (unthrottled loopback, not directly comparable to the networked lab numbers above): carta-digital 2892ms/0.0025, tarjetas-nfc 3174ms/0.3372, tpv-restaurantes 2603ms/0.0009, home 2271ms/0.0035. The #421 console error — this slice's actual target — is fully eliminated on every route that previously carried it.

**Deviations from design:** none — matches design.md D1/D2 exactly. **Follow-ups:** S2–S9 remain, in merge order, on top of this branch, per `tasks.md`.

## S2 — Security + head hygiene (branch `feat/followups-s2-security-head`, 2026-10-02)
**Why.** `index.html` restricted `Permissions-Policy` via `<meta http-equiv="Permissions-Policy">`, which browsers ignore — that directive is only honored as a real HTTP response header. Two more metas were dead weight: `<meta http-equiv="X-Content-Type-Options">` (the real header was already set in `vercel.json`) and `<meta http-equiv="X-UA-Compatible">` (IE-only, no effect in any currently supported browser). `<meta charset="UTF-8">` sat after two inline `<script>` blocks instead of being `<head>`'s first child (the HTML spec requires it within the first 1024 bytes to avoid a re-parse). The Consent Mode comment above `gtag("consent", "default", …)` read "nothing measured until explicit opt-in," which overstates what the code does: `gtag.js` still loads unconditionally and `dataLayer` pushes happen before any consent decision, only the `*_storage` grants are denied.

**What changed (design.md D5):**
- **`vercel.json`**: added a `Permissions-Policy` header to the global `/(.*)` rule — `camera=(), microphone=(), geolocation=(), payment=(), usb=(), magnetometer=(), gyroscope=(), accelerometer=(), browsing-topics=()`. A source scan found no use of any of these browser features, so every directive is a safe deny. `'unsafe-eval'` in the CSP `script-src` is untouched (task 2.4; out of scope, tracked as a follow-up in the proposal's Risks table).
- **`index.html`**: removed the 3 dead `<meta http-equiv>` tags (`Permissions-Policy`, `X-Content-Type-Options`, `X-UA-Compatible`); kept the real `<meta name="referrer">` (functionally honored, unlike the http-equiv tags). Moved `<meta charset="UTF-8">` to be the first child of `<head>`. Rewrote the Consent Mode comment to state that `gtag.js` still loads and may send cookieless pings pre-opt-in, and that no analytics cookies are set until the user grants consent.
- **New test:** `tests/unit/scripts/securityHeaders.test.ts` — asserts the `Permissions-Policy` header and its directive list on `vercel.json`'s global rule, absence of the 3 dead meta tags, charset-first-child, and that the Consent Mode comment names `gtag.js`'s actual pre-consent behavior.

**TDD evidence.** RED: ran before any implementation — all 6 assertions failed for the correct cause (header missing from `vercel.json`, all 3 dead metas still present in `index.html`, charset not the first head child, comment still read the old "nothing measured" text). GREEN: all 6 pass after the `vercel.json`/`index.html` edits above.

**Verification.** `npx jest` 1351/1354 (same 3 pre-existing unrelated `chatbotFlow.test.ts` network failures as S1/`develop`, nothing new). `npm run test:vitest -- --run` 112/112. `npx tsc --noEmit` clean. `npm run lint` clean (0 warnings). `npm run build`/`npx jest tests/unit/seo` deferred to the owner-authorized build after S4 per the run's instructions (S2 and S3 are config/test-only — no behavior that a fresh `dist/` would catch that the targeted test doesn't already cover).

**Manual preview check (task 2.6).** Not performed this run — no live Vercel preview deployment is available in this execution environment. `Permissions-Policy` is covered structurally by the new header test; a live console/header check against a deployed preview is recommended before this branch merges to main.

**Deviations from design:** none for the Permissions-Policy header, meta removal, charset ordering, or Consent Mode text — all match design.md D5 and the Interfaces/Contracts `index.html` section exactly. The open question in design.md ("drop X-Content-Type-Options/X-UA-Compatible too?") is resolved by tasks.md 2.2/2.3, which explicitly lists both metas — both are removed.

## S3 — Regression guards (branch `feat/followups-s3-regression-guards`, 2026-10-02)
